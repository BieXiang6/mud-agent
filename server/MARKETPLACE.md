# Skill 与脚本市场

市场与版本/公告共用 `npm run server` 服务和 `VITE_RELEASE_API_BASE_URL` 地址。客户端从 Skills 或游戏脚本页进入，分类、搜索、分页挑选内容，查看源码后下载到本机或另存 JSON。下载不会运行脚本；本机同名内容被替换前会确认，内置 Skill 不允许被覆盖。

## 昵称与私密签名

首次使用时，用户登录游戏账号，点击市场右上角“上传”旁的“登录”，在弹窗中输入一个未注册昵称并点击“注册昵称并继续”。服务器生成 256 位随机私密签名，仅在注册成功响应中返回一次，客户端自动保存在本机。服务器只持久化签名的 SHA-256 哈希，不保存可恢复的签名原文。

昵称经过 Unicode NFKC 规范化，忽略首尾空格和字母大小写，全市场唯一。已有昵称返回 409，不会重新签发签名，即使请求者填写相同游戏账号也不会补发。

身份绑定游戏账号名，不包含游戏服务器 IP、端口、区服后缀、密码或编码。同一游戏账号更换服务器或区服后，客户端继续使用原昵称和签名；切换游戏账号则分别使用各自保存的昵称身份。市场作者显示昵称，服务端从已验证的签名身份生成作者信息，忽略客户端伪造的 authorId 和作者元数据。

每个游戏账号只绑定一个昵称。新客户端即使改填其他昵称，也不能为已绑定账号重新注册，必须导入原签名后继续。

注册时的游戏账号由客户端当前在线会话填写；市场服务没有游戏密码校验接口。持有私密签名是已有昵称的使用和更新依据，只有账号名不能冒充已有昵称。此模式不验证新注册昵称所声明的游戏账号是否真实归其所有。

## 换客户端

1. 在旧客户端登录对应游戏账号，打开市场，点击右上角昵称进入账号弹窗，再点击“导出私密签名”。
2. 将导出的 `mud-market-identity.json` 文件转移到新客户端。
3. 新客户端打开市场，点击右上角“登录”，在弹窗中点击“导入私密签名”。服务端验证成功后才保存到本机。
4. 登录绑定的同名游戏账号，即可继续使用原昵称上传和更新原有作品。

文件包含昵称、绑定账号和私密签名，持有者可以使用此市场身份，请妥善保存。签名不会显示在市场列表、普通内容包或日志中。服务器没有按昵称找回、重复签发或自动恢复签名的接口；旧客户端和导出备份均丢失时，不能仅凭昵称恢复身份。导入无效或伪造文件不会覆盖本机现有签名；替换同账号的其他昵称前会确认。

## 部署与存储

服务端环境变量 `MARKET_DATA_DIR` 指定持久化目录，默认 `server/data/market`：

- `items.json`：内容、版本、描述、作者、服务端更新日期及每日上传计数，使用 version 2 快照原子保存。
- `identities.json`：唯一昵称、绑定账号、签名哈希及昵称禁用状态。
- `blocked-accounts.json`：禁止注册、上传和更新的游戏账号名单。

备份整个目录。文件原子写入，文件后端供单个服务进程使用。通过 HTTPS 反向代理提供公网访问，以保护传输中的私密签名。代理需放行 GET、POST、PUT、DELETE、OPTIONS 和 Authorization 请求头，允许至少 256 KB 的请求体。

旧版 `accounts.json` 和 `issuer.json` 不再参与昵称认证，不要据此公开发放已有昵称签名。旧版市场条目保留浏览和下载，但旧凭证不能更新或接管新的昵称身份。

## 禁用与恢复

在服务器项目目录执行，昵称含空格时用引号包围：

```bash
npm run market:admin -- block "江湖客"
npm run market:admin -- unblock "江湖客"
npm run market:admin -- block-account hero
npm run market:admin -- unblock-account hero
```

昵称禁用会阻止该身份上传、更新和通过签名验证。账号禁用会阻止该账号的所有昵称上传、更新，并阻止其注册新昵称，避免换昵称绕过禁用。限制每次请求即时读取，无需重启；已发布内容仍可浏览下载。管理员没有重新签发已有昵称私密签名的命令。

## 内容更新

本机保存内容后，进入市场“上传”，选择本机条目，填写名字、描述和版本后发布。原作者条目显示“更新内容”，导入原私密签名的新客户端也可更新。服务端校验签名、绑定账号、禁用状态、作者身份和修订号；同作者同类型同名条目不可重复发布。更新须使用新的版本号，并发修改返回 409，刷新后重试。

## 每日上传额度

每个游戏账号每天最多新上传 4 个内容，Skill 和脚本合并计算，按北京时间（Asia/Shanghai）每天零点重新计算。昵称“想都别想”经私密签名验证后不受此额度限制；伪造请求中的昵称不能获得豁免。

更新已有内容、校验失败和未成功保存的请求不消耗新上传次数；删除作品不会返还当日次数。额度绑定游戏账号，不随游戏服务器、区服、客户端或私密签名导入迁移而改变。服务器串行检查和提交新上传，条目与计数写在同一份原子快照中，重启后仍保留。达到上限时新上传接口返回 429，已有内容仍可更新、浏览、下载及按权限删除。

权限接口返回 `dailyUploadQuota`，含当日日期、时区、已用次数、限额、剩余次数和下次重置时间。管理员的 unlimited 为 true，limit 和 remaining 为 null。客户端发布弹窗显示当日用量。

旧数组格式的 `items.json` 会按已有作品的 createdAt 和绑定账号初始化历史计数，第一次写入时自动迁移为 version 2 快照，不修改作者身份或私密签名。升级前应备份数据；回退到旧版数组存储代码时，需同时恢复升级前的数据备份。

## 删除权限

作者可以在列表或详情中删除自己发布的市场内容；昵称为“想都别想”的已验证身份可以删除任意作者的内容。服务端依据私密签名匹配到的真实昵称与作者 ID 判定权限，伪造请求中的昵称或 authorId 不会获得权限。管理员的全部删除权限不包含更新他人内容。

删除前客户端弹窗确认，并提交条目修订号，防止误删确认期间被更新的内容。删除后立即从市场列表及下载接口移除，本机已下载的脚本、Skill 和签名保留。禁用昵称或游戏账号同样不能执行删除。

## HTTP 接口

响应格式为 `{ success, data }` 或 `{ success: false, error }`。

| 接口 | 用途 |
| --- | --- |
| `POST /api/market/identities` | 首次注册 `{ nickname, account }`，唯一一次返回 privateSignature |
| `POST /api/market/permission` | 验证 `{ author: { nickname, account } }` 与 Bearer 私密签名，返回公开身份及上传权限 |
| `GET /api/market/items?type=skill&q=关键词&offset=0&limit=20` | 分类、名字/描述/作者昵称搜索和分页，limit 最大 50 |
| `GET /api/market/items/:id` | 查看内容及元数据 |
| `POST /api/market/items` | 上传新内容 |
| `PUT /api/market/items/:id` | 原作者更新，需传 expectedRevision |
| `DELETE /api/market/items/:id` | 作者删除自己的内容，或“想都别想”删除任意内容；需 author、expectedRevision 和 Bearer 私密签名 |

上传和更新使用 `Authorization: Bearer <privateSignature>`，JSON 中包含 `author: { nickname, account }`、`type`、`name`、`description`、`version`、`payload`。Skill payload 包含 content 和可选 disableModelInvocation；脚本 payload 包含 source。id、authorId、revision、createdAt、updatedAt 由服务端生成，客户端与服务端共用内容验证规则，服务端不执行上传内容。旧 `/api/market/credentials` 接口已移除。
